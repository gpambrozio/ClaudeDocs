# [Claude docs changes for September 16th, 2026](https://github.com/gpambrozio/ClaudeDocs/tree/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee) [[diff](https://github.com/gpambrozio/ClaudeDocs/commit/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee)]

## Executive Summary
- **On-demand compaction arrives** behind the `compact-2026-09-04` beta: send a top-level `compaction` parameter and get back a single signed block with no reply, so the summary can be generated in the background while the conversation keeps running, and recent turns can be kept word-for-word after it
- New `gatewayInternalNetworks` managed setting lets organizations whose internal network is numbered from public IPv4 space they own sign in to a Claude apps gateway there — with a carefully-bounded validation regime: at most four non-overlapping blocks, none touching private, documentation, or reserved space
- New Agent SDK "Configure your agent" page pulling options, settings files, environment variables, model selection, limits and mid-session changes into one place
- `PostToolUse` hooks can now receive the files a Bash command changed in `tool_response.bashEditDiff`, with explicit honesty about its limits: "best effort and in public beta… use the list to find what to review, not to enforce a policy"
- The per-language SDK reference pages were regenerated so every type declaration carries its language keyword (`interface`/`type` in TypeScript, `class` in Python, Java and C#, `type` in Go) — a cosmetic change that accounts for the great majority of this commit's 155,000 changed lines

* Fixed Bash commands the permission checker can't fully analyze skipping the prompt under `permissions.blockReadsOutsideWorkingDirectories`, and a subshell hiding a dangerous `rm` in bypass mode

* Fixed the context meter and auto-compact counting advisor-tool turns at roughly **twice** their real size, which made auto-compact fire at about half the real window
* Fixed `/login`, `/upgrade` and `/extra-usage` discarding earlier thinking, forcing a full prompt-cache rewrite on the next request
* Fixed subagents and background agents being reported as failed, with their result never delivered, when the final streamed reply omitted token usage or carried no model id
* Fixed Read on macOS refusing a dragged-in screenshot with "symlink resolution changed after permission was checked"
* Fixed saved scheduled tasks running in the wrong session after `.claude/scheduled_tasks.json` was copied into another folder, such as a new worktree

## API changes

### Changed documents

#### [build-with-claude/compaction](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md) [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction)]

* New "Compact on demand with the `compaction` parameter" section, roughly 140 lines documenting the `compact-2026-09-04` beta. The shape: send your conversation with `"compaction": {"type": "summarize"}`, the API summarizes every message once, generates no reply, and returns a single signed block alone with `stop_reason: "compaction"`. From then on that block goes **first** in `messages`, replacing what it summarized — and leaving the summarized messages in front of it is a 400. This inverts threshold compaction, whose block *follows* the messages it summarizes. [[lines 3384-3386](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md?plain=1#L3384-L3386)] [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction#compact-on-demand-with-the-compaction-parameter)]
* The three things it buys you: you choose when to compact; the summarization request can run in the background while the conversation continues on its full history (async compaction); and you can keep recent turns word-for-word after the summary (keep-tail compaction) — with their thinking still valid on preserved-thinking models. [[line 3388](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md?plain=1#L3388)] [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction#compact-on-demand-with-the-compaction-parameter)]
* Billing and limits: the summarization call uses the request's model, `system`, `tools`, thinking settings and `max_tokens`, is billed and rate-limited like any request, and reports as the `compaction` entry in `usage.iterations` — while the **top-level `input_tokens` and `output_tokens` are zero** because no reply was generated. `max_tokens` caps the whole call including pre-summary thinking, so allow several thousand tokens. [[line 3454](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md?plain=1#L3454)] [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction#request-a-summary)]
* Rejections up front: a trailing tool call with no result yet, `stop_sequences`, structured-output `output_config.format`, and a `tool_choice` of `any` or `tool` are all refused. And the conversation must still fit the context window, so **compact before you outgrow it, not after**. [[line 3456](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md?plain=1#L3456)] [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction#request-a-summary)]
* The async swap given as pseudocode: drop exactly the messages you sent in the compaction request from the front of your history, put the returned message in their place, keep everything appended since — and don't edit your history in between, making the swap on the first request after the block arrives, so thinking produced while the summary was being written stays valid. [[lines 3498-3509](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md?plain=1#L3498-L3509)] [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction#continue-from-the-summary)]
* A subtle constraint on keep-tail: the first kept message mustn't be one the API would merge into the last summarized message — same role, or a `role: "system"` message. The simplest way to satisfy it is to compact exactly the `messages` of a request you already made, and to change `system` or `tools` without invalidating kept thinking, compact the whole conversation first so nothing is kept. [[line 3516](https://github.com/gpambrozio/ClaudeDocs/blob/d73d5d59d10fdf51c0fba435f6ec4c718e8d7bee/docs-md/api/build-with-claude/compaction.md?plain=1#L3516)] [[Source](https://platform.claude.com/docs/en/build-with-claude/compaction#continue-from-the-summary)]
* Custom `instructions` (up to 16,384 characters) replace the API's prompt entirely, and here the summarizer **reads the whole conversation including earlier thinking with or without them** — unlike threshold compaction on Fable 5.1 and Mythos 5.1, where custom instructions leave earlier thinking out.
